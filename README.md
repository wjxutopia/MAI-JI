# 麦记（Mai-Ji）

> **爱吃的就那几样，怎么点更省？** 麦记把套餐、单点和当前优惠一起算，找同样需求更省的买法；`老样子` 一句话复购，付款前也能检查这单。

## 能做什么

你继续用原生点餐页面看商品、选门店、填地址和付款；麦记不重做这些步骤。它只在需要的时候帮你把**已经想吃的东西**按当前规则重新算一遍：原单该保留，还是有同样需求、更省的买法。

| 你的情况 | 你说 | 麦记做什么 |
|---|---|---|
| 一直点固定几样 | `老样子` / `再来一单` | 读取你明确保存的常点，按今天的门店、菜单和价格重新核价；不沿用旧价格或旧套餐。 |
| 已经在原生页面点好了 | `检查刚才这单` / `这单还能省吗` | 读取普通食品待支付单，在相同履约条件下比较套餐、单点和当前可核验优惠。 |
| 没有待支付单或常点 | 直接说完整需求 | 按当前菜单建立本次基线；只在缺少决定性条件时追问。 |
| 几个人一起点 | 说明人数、预算和必需商品 | 在硬约束内找组合；预算不够会如实说明，不会偷偷少商品。 |

第一次使用“检查刚才这单”时，先在原生点餐页面选好餐并提交为**待支付订单**，不要付款；然后回到对话里说这句话即可。

## 一次给出可执行选择

麦记内部会拆套餐、比较商品、核对优惠和计算完整应付；正常情况下只给你一个主要结论，至多再给一个有意义的新增商品选项。

下面是**合成示例**，商品、金额和卡号都不是实时报价：

```text
你：检查刚才这单

麦记：
本次已核验范围内，同店同址，外送含配送和打包：

1｜¥30.00 保留原单：汉堡 1 个＋薯饼 1 份，不新建。
2｜¥27.00 新建：同款汉堡 1 个＋薯饼 1 份＋小杯豆浆 1 杯；
   核对成功后取消原单。比原单低 ¥3.00，豆浆为新增商品。

卡 aaaaaaaaaaaaaaaa · 有效至 HH:mm
回复编号执行，最后自行支付。

你：2
```

- 只有商品、规格、数量、已知明确备注和履约条件都满足，且**完整应付更低**，才叫“更省”。
- 同价或更低但多出商品，只会作为单独选项展示；例如上面的豆浆，必须由你这次选中，绝不会默认加入订单。
- 选中后会再次检查价格、库存、优惠、订单状态和履约条件。可以替换时，顺序固定为：**先建新单 → 核对新单 → 再取消旧单**。
- 没有可靠可执行的更省方案，就保留原单；付款始终由你自己完成。

## 下单规则

| 规则 | 实际含义 |
|---|---|
| 不擅自换餐 | 你指定的商品、口味、规格、数量和明确备注都是硬约束。 |
| 新增商品必须确认 | 新增商品即使更便宜，也必须本次明确选择。 |
| 常点不带旧价格 | 常点记住的是“吃什么”，不是旧菜单、旧套餐或旧报价。 |
| 不自动支付 | 麦记只创建或替换待支付订单；付款入口和付款动作仍由你控制。 |
| 结果不清楚就停止 | 费用不完整、优惠占用不明、备注无法可靠保留、创建结果未知时，不会反复建单。 |

普通餐品按标准出品处理；你明确提出的“不要酱”等备注会被严格保留。当前接口无法可靠传递或核对时，麦记会说明原因并保留原单。

## 怎么接入

麦记以 Skill 指令、参考规则、本地状态工具和 MCP 配置示例交付。其他 Agent/模型宿主可按自身能力接入，但必须在目标宿主中自行验证兼容性。

运行一个可安全创建或替换订单的实例，宿主至少需要：

1. 能加载 [`SKILL.md`](./mai-ji/SKILL.md) 以及同目录的 `references/`、`scripts/` 文件；
2. 能连接 Streamable HTTP MCP，并调用当前麦当劳 MCP 暴露的工具；
3. 能执行 Python 3.10+，供本地状态与防重工具运行；
4. 能为同一账号保留一个位于 Skill 包外的稳定本地数据目录。

不同宿主的导入格式、MCP 配置位置和 Python 执行方式不同。按你的宿主实际支持情况选择下面的接入方式：

### 1. 配置麦当劳 MCP

按[麦当劳 MCP 官方指南](https://github.com/M-China/mcd-mcp-server)取得自己的 Token。仓库提供 [`mcp-config.example.json`](./mcp-config.example.json)，它是常见 `mcpServers` 格式的 Streamable HTTP 示例：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

将 `url`、认证头和传输类型映射到你所用宿主的等价配置中。真实 Token 只在本机注入，不能写进仓库、Skill、截图或日志。实际调用流程见 [MCP 集成说明](./MCP_INTEGRATION.md)。

### 2. 加载 Skill

- **宿主明确支持导入此类 Skill ZIP：** 导入 [`dist/mai-ji-v1.2.0.zip`](./dist/mai-ji-v1.2.0.zip)。
- **宿主支持从本地目录或 Markdown 加载 Skill：** 加载 [`mai-ji/SKILL.md`](./mai-ji/SKILL.md)，并保留同目录的 `references/` 与 `scripts/`；不要只复制一段提示词后丢掉状态协议与安全规则。
- **宿主不具备 MCP、Python 或持久化状态能力：** 可以阅读和改造逻辑，但不应把它当作可安全执行创建/替换订单的完整运行环境。

### 3. 设置本地状态目录

运行状态必须放在 Skill 包外，同一账号持续使用同一个数据目录和 scope；不要把数据库、Token、支付链接、完整地址或订单原始响应打包进项目。

```text
ABS_PYTHON -B SKILL_ROOT/scripts/guard.py --db ABS_DATA_DIR/guard.sqlite3
```

完整运行协议、升级注意事项和本地数据边界见 [运行与本地状态说明](./mai-ji/references/runtime.md)。

## 当前范围

- 面向**普通食品订单**；当前按可读取、可核验的到店与立即外送链路处理。
- 不处理积分商城订单、预约、得来速、团餐、自动领券、购买会员、创建地址或自动支付。
- 菜单、供应和优惠会变化；每次只说明“本次已核验范围内”的结果，不承诺全网最低价。
- 优惠券占用/释放、真实超时、跨设备并发、全部原生来源和明确备注回显尚未全覆盖；这些情况会降级或停止，不会伪造成功。
